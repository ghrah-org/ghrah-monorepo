# ghrah.mcp 使用手册

把一台 MCP 服务器的连接声明变成可执行的工具调用。本手册面向在本仓库内集成 MCP 能力的开发者。

| 项 | 值 |
| --- | --- |
| 文档版本 | 1.0 |
| 适用代码 | `ghrah-core/src/ghrah/mcp/`（Python 3.11+） |
| 读者 | 在 ghrah 侧接入 MCP 服务器的开发者、维护技能配置的开发者、排查 MCP 调用失败的运维/测试 |
| 不在范围 | MCP 协议规范本身、agentconf 的完整用法、对外发布的 HTTP API |

## 文档说明

### 目的与范围

本手册回答三个问题：**怎么把一次 MCP 调用跑起来**、**每一层 API 各自负责什么**、**失败时怎么定位**。它不解释协议细节（那是上游规范的事），也不教你写技能配置（那是 `ghrah.scheme_ability` 的职责）。

### 读者对象

- **集成开发者**：要在自己的模块里发起 MCP 调用。读第 1、3、4、5 章即可开工。
- **配置维护者**：维护 agentconf 里的服务器记录与工具白名单。重点读第 3、6、7 章。
- **排障者**：被一条异常挡住。直接跳到第 9、12 章。

### 术语表

| 术语 | 含义 | 代码里的名字 |
| --- | --- | --- |
| 服务器 | 一个 MCP 端点（一个 URL），是规范中的作用单位 | `server` / `McpServerSpec` |
| 工具 | 服务器上的一个可调用方法，名字扁平、无命名空间 | `tool` / `McpToolSpec` |
| 白名单 | 声明「这台服务器允许调用哪些工具」，来自本地配置 | `spec.tools` |
| 技能 | 声明 MCP 能力的宿主单元，同时是授权边界 | `skill_full_name` |
| 作用域 | 一次装配/一次 agent 会话的隔离边界 | `agent_scope` |
| 凭据占位符 | 请求头里唯一允许的变量，解析期替换成密钥 | `AUTH_PLACEHOLDER`（`{{auth}}`） |
| 凭据解析器 | 按服务器地址给出密钥的回调 | `CredentialResolver` |
| 会话 | 一台服务器的连接句柄持有者，可跨多次调用复用 | `McpSession` |
| 运行时 | 已激活集合与连接的持有者，生命周期与 agent 会话一致 | `McpRuntime` |
| 投影 | 把 MCP 原始结果压成框架可用的文本/结构 | `project_result` |

### 阅读约定

- 代码块中的 `SPEC` 均指一个已构造好的 `McpServerSpec`，其完整定义见 1.2。
- 「调用函数」给出的是**当前签名**，以函数定义为准；本手册不重复类型标注细节。
- 标 **踩坑** 的条目是实践中真实踩过的分支，不是推测。

## 1. 快速上手

### 1.1 依赖

本包依赖三个运行时库，均已在本仓库声明：

| 依赖 | 用途 | 说明 |
| --- | --- | --- |
| `mcp` | MCP SDK（客户端、传输、类型） | **只有 `client.py` 直接 import 它**，其余模块通过本包的类型别名间接使用 |
| `agentconf` | 凭据与服务器记录的本地库 | 可选路径：不使用 agentconf 时不会 import 它 |
| `httpx2` | HTTP 客户端与诊断探测 | 由 `diagnostics.py` 直接使用 |

### 1.2 第1步：写一份服务器声明

手工构造（测试、脚本、无 agentconf 的场景）：

```python
from ghrah.mcp import McpServerSpec, McpToolSpec

SPEC = McpServerSpec(
    skill_full_name="demo/web",  # 谁声明了它：授权作用域
    server="web",  # 服务器名：小写字母/数字/下划线，≤32 字符
    url="https://mcp.example.com/mcp",
    headers={"Authorization": "Bearer {{auth}}"},  # 密钥不进代码
    tools=(
        McpToolSpec(
            name="web_fetch",
            description="抓取一个网页并返回正文",
            input_schema={
                "type": "object",
                "properties": {"url": {"type": "string"}},
                "required": ["url"],
            },
        ),
    ),
)
```

从 agentconf 读取（生产路径，推荐）：

```python
from ghrah.mcp import AgentconfMcpSource

with AgentconfMcpSource() as source:  # 默认读 ~/.agentconf/config.db
    spec, credential = source.spec_and_credential("阿里云网页解析mcp", skill_full_name="demo/web")
```

### 1.3 第2步：连一次，看看服务器上到底有什么

```python
import asyncio
from ghrah.mcp import call_tool_once, list_tool_names, open_client


async def peek() -> None:
    async with open_client(SPEC, credential="sk-xxxxxxxx") as client:
        names = await list_tool_names(client)  # 跟分页游标取尽
        print("服务器上的工具:", names)

        outcome = await call_tool_once(client, "web_fetch", {"url": "https://example.com"})
        print("is_error =", outcome.is_error)
        print(outcome.text[:200])


asyncio.run(peek())
```

**踩坑**：`list_tool_names` 只用于诊断与校验。工具清单来自本地配置（`spec.tools`），运行时**不需要**联网获取——不要把它塞进启动路径。

### 1.4 第3步：用运行时执行调用

```python
import asyncio
from ghrah.mcp import McpRuntime, StaticCredentials


async def run() -> None:
    runtime = McpRuntime(credentials=StaticCredentials({SPEC.url: "sk-xxxxxxxx"}))
    try:
        await runtime.activate(SPEC, agent_scope="session-1")
        outcome = await runtime.call(
            agent_scope="session-1",
            server="web",
            tool="web_fetch",
            arguments={"url": "https://example.com"},
        )
        print(outcome.render_for_model())
    finally:
        await runtime.close()


asyncio.run(run())
```

### 1.5 跑起来应该看到什么

- 第2步：打印出服务器真实工具名（例如 `('web_fetch',)`），`is_error` 为 `False`，`text` 是工具返回的正文。
- 第3步：`render_for_model()` 输出正文；若结果里含被丢弃的二进制内容，会额外附一行诊断（见 8.2）。

出现以下任一情况，说明还没跑通：抛 `McpCredentialMissingError`（没配密钥）、抛 `McpNotActivatedError`（没激活）、打印 `is_error = True`（工具自己报错，见 9.6）。

### 1.6 最小可用清单

装完并跑通后，下面四行应该都能填上；填不上的那行就是没做完的部分。

| 组件 | 属性 | 值 |
| --- | --- | --- |
| 服务器声明 | `server` / `url` | 自填 |
| 工具白名单 | `tools` | 至少一个工具，描述非空 |
| 凭据 | 来源 | agentconf provider 或 `StaticCredentials` |
| 连接 | 协议偏好 | 默认 `modern-first` |

## 2. 核心概念

### 2.1 本包的位置

`ghrah.mcp` 与 `ghrah.scheme`（能力 + 技能）**并列**，不 import 它们中的任何一个。它只做一件事：把连接声明变成工具调用。

```
技能配置 ──解析──> McpServerSpec + 凭据 ──> ghrah.mcp ──> MCP 服务器
                        ▲                      │
                        └── ability 层反向依赖 ─┘
```

三个由此推出的结论：

- **本包不解析任何配置文件**。`McpServerSpec` 由技能模块产出后传进来。
- **本包不持有工具目录**。它只拿「能调哪些工具名」这份授权集合（`spec.tools`）。
- **工具信息全部来自本地配置**，读取全程离线；代价是 schema 是快照（见 2.3）。

### 2.2 服务器、工具与白名单

一台服务器对应一个 URL（Streamable HTTP 只有一个端点），服务器内按工具名路由。工具名**扁平、无命名空间**，作用域仅限本服务器——所以 `(server, tool)` 必须成对定位。

`spec.tools` 是白名单，不是缓存：

| 情形 | 行为 |
| --- | --- |
| `tools=()` | 服务器可以激活，但任何调用都在白名单校验处失败 |
| 工具名不在白名单 | 抛 `McpToolMissingError`，**不建连**（凭据都不会被使用） |
| 工具名重复 | 构造 `McpServerSpec` 时立刻抛 `McpConfigError` |

### 2.3 两个设计取舍与其代价

**取舍一：工具信息全部来自本地配置。**

读取技能声明的 MCP 能力全程离线，服务器宕机、凭据缺失都不影响「有哪些工具」可见。代价是 `input_schema` 是快照，可能与服务器实际不一致，需要靠生成/校验工具维护。

**取舍二：面向模型的执行入口只有一个。**

工具不注册成独立函数，而是通过统一的 `mcp_call(server, tool, arguments)` 传入。好处：工具列表恒定（不打断提示词前缀缓存）、免去把任意工具名改造成合法函数名（截断、加哈希、反解）这一整类问题。

**推论**：`activate()` 是纯内存操作、不联网；想拿远端真实清单做校验，必须显式调用 `list_tool_names`。

### 2.4 作用域：`skill_full_name` 与 `agent_scope`

| 字段 | 谁用 | 语义 |
| --- | --- | --- |
| `spec.skill_full_name` | `activate` 冲突判定、`call(skill=...)` 归属校验 | 声明该服务器的技能；「哪些工具可见」的边界 |
| `agent_scope` | 激活集合与连接的键 | 一次装配/一次会话；同一 agent 内服务器名必须唯一 |

同一 `agent_scope` 下，两个**不同技能**声明同名服务器会在 `activate` 时立刻抛 `McpConfigError`——调用参数里没有技能维度，留着只能在调用期猜一个。

### 2.5 凭据占位符

请求头里**至多一个**可以包含 `{{auth}}`：

```python
headers = {"Authorization": "Bearer {{auth}}", "X-Trace": "on"}  # 合法
headers = {"Authorization": "Bearer {{auth}}", "X-Key": "{{auth}}"}  # 抛 McpConfigError
```

解析发生在建连前（`resolve_headers`）：占位符替换成该地址的密钥。缺密钥时**不发请求**，直接抛 `McpCredentialMissingError`（fail-closed）——宁可明确说「没配」，也不要发一个注定 401 的请求。

**踩坑**：只认 `{{auth}}` 一种写法。写 `{{api_key}}` 会被判为不支持的占位符；写 `${TOKEN}` 这类模板直接抛 `McpConfigError`——残留的模板发出去必然被服务器拒绝，还会掩盖真正的配置错误。

### 2.6 协议协商

三档偏好，映射到 SDK 的 `mode`：`modern-first` → `auto`、`legacy` → `legacy`、`2026-07-28` → 固定版本。详见第 10 章。

### 2.7 会话与代际

`McpSession` 持有一台服务器的连接，可跨多次调用复用；每次建连或断开都会让 `generation` 递增，便于日志与陈旧判断。会话被服务端丢弃时先丢弃句柄再关闭，下次调用重建，绝不复用半坏的连接。

## 3. 数据结构

### 3.1 `McpServerSpec`

`@dataclass(frozen=True)`——**不可变**。要改字段用 `dataclasses.replace`，不要赋值。

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `skill_full_name` | `str` | 必填 | 声明它的技能；非空 |
| `server` | `str` | 必填 | 服务器名，须匹配 `^[a-z][a-z0-9_]*$`，≤32 字符 |
| `url` | `str` | 必填 | 必须 http(s)、有主机、无内嵌凭据、无空白 |
| `headers` | `Mapping[str, str]` | `{}` | 至多一个含 `{{auth}}`；名字不含空白与 `:`，值不含控制字符与 `${...}` 模板 |
| `tools` | `tuple[McpToolSpec, ...]` | `()` | 白名单；重名报错 |
| `transport` | `Transport` | `streamable-http` | 目前只支持这一个值 |
| `protocol` | `ProtocolPreference` | `modern-first` | 协商偏好 |
| `connect_timeout_ms` | `int` | `60000` | 建连超时，必须为正 |
| `execution_timeout_ms` | `int` | `300000` | 单次调用总预算，必须为正 |
| `max_result_bytes` | `int` | `2000000` | 结果体积上限 |
| `max_pages` | `int` | `50` | 分页上限，≤500 |

派生属性：

| 属性 | 返回 | 用途 |
| --- | --- | --- |
| `tool_names` | `tuple[str, ...]` | 白名单工具名，保持配置顺序 |
| `credential_headers` | `tuple[str, ...]` | 携带占位符的头名（跨源重定向时必须剥掉） |
| `requires_credential` | `bool` | 是否引用了占位符 |
| `find_tool(name)` | `McpToolSpec \| None` | 查白名单，未命中返回 `None` |
| `require_tool(name)` | `McpToolSpec` | 查白名单，未命中抛 `McpToolMissingError`（带可用清单） |

**踩坑**：`credential_headers` 不能写死 `Authorization`——凭据可能放在任意名字的头里，这也是它返回元组的原因。

### 3.2 `McpToolSpec`

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | `str` | 必填 | 服务器上的原名，**不做归一化**；≤128 字符、不含空白与控制字符 |
| `description` | `str` | 必填 | 写给人看的「何时使用」，非空；目录渲染直接用它 |
| `input_schema` | `Mapping[str, Any]` | `{}` | 必须是最外层 JSON 对象；零参数工具为 `{}` |
| `read_only` | `bool` | `False` | 只影响「失败后能否自动重放」；默认按可写处理 |

方法 `render_schema(*, max_bytes=None) -> SchemaRender`：返回整形后的 schema 文本，超限降级为摘要（见 7.4）。

**踩坑**：`read_only` 与服务器声明的 `readOnlyHint` 是两回事。工具清单来自本地配置，运行期不取服务器标注，因此这个判断依据也只能是配置。

### 3.3 枚举

| 枚举 | 成员 | 值 |
| --- | --- | --- |
| `Transport` | `STREAMABLE_HTTP` | `"streamable-http"` |
| `ProtocolPreference` | `MODERN_FIRST` / `LEGACY` / `MODERN` | `"modern-first"` / `"legacy"` / `"2026-07-28"` |

`Transport` 只声明一个值，是为了让「子进程传输尚未支持」在类型层就暴露，而不是等运行期报一个含混的连接错误。

### 3.4 默认值速查

| 常量 | 值 | 出处 |
| --- | --- | --- |
| `DEFAULT_CONNECT_TIMEOUT_MS` | `60_000` | `spec.py` |
| `DEFAULT_EXECUTION_TIMEOUT_MS` | `300_000` | `spec.py` |
| `DEFAULT_MAX_RESULT_BYTES` | `2_000_000` | `spec.py` |
| `DEFAULT_MAX_PAGES` | `50` | `spec.py` |
| `MAX_PAGES_LIMIT` | `500` | `spec.py` |
| `MAX_SERVER_NAME_LEN` | `32` | `identity.py` |
| `MAX_TOOL_DESCRIPTION_CHARS` | `500` | `identity.py` |
| `DEFAULT_MAX_SCHEMA_BYTES` | `8192` | `schema.py` |
| `DEFAULT_PROBE_TIMEOUT_S` | `5.0` | `diagnostics.py` |

## 4. 连接与调用（无状态 API）

这一层不持有状态，适合脚本与一次性检查；需要复用连接时见 5.6。

### 4.1 `open_client`

```python
@asynccontextmanager
async def open_client(
    spec: McpServerSpec,
    *,
    credential: str | None = None,
    read_timeout_s: float | None = None,
) -> AsyncIterator[mcp.Client]
```

建立连接并 yield 已握手完成的客户端。

| 参数 | 说明 |
| --- | --- |
| `credential` | 密钥明文；`spec.requires_credential` 为真且此处为空 → 抛 `McpCredentialMissingError` |
| `read_timeout_s` | **单次请求**的读超时，不是整次调用的预算；整次预算由上层包裹 |

失败（连接、握手）一律翻译成 `McpError` 子类；`CancelledError` 原样穿透。握手失败时会自动补一次 HTTP 探测，把 401/404 区分出来（见 9.5）。

### 4.2 `call_tool_once`

```python
async def call_tool_once(
    client: mcp.Client,
    tool_name: str,
    arguments: Mapping[str, Any] | None,
    *,
    read_timeout_s: float | None = None,
) -> ToolOutcome
```

**工具级失败不会抛异常**：服务器返回的错误（含工具内部异常）已被 SDK 归一成 `is_error=True` 的结果。异常只用于连接与协议层失败。

### 4.3 `list_tool_names`

```python
async def list_tool_names(client: mcp.Client) -> tuple[str, ...]
```

跟随分页游标取尽全部工具名。**仅用于诊断与校验**（例如确认配置里声明的工具是否仍然存在）。`max_pages` 的约束由调用方以超时或取消施加。

### 4.4 `resolve_headers`

```python
def resolve_headers(spec: McpServerSpec, credential: str | None) -> dict[str, str]
```

把占位符替换成最终发送值。只在建连前调用；缺凭据时 fail-closed。

### 4.5 `read_only_hint`

```python
def read_only_hint(tool: types.Tool) -> bool
```

取服务器标注的只读提示。**未标注时返回 `False`**：把「不知道」当「只读」会在写工具上造成重复执行，而这个错误无法撤销。

### 4.6 `McpSession`

持有连接、复用连接、在会话失效时重建。

```python
session = McpSession(spec, credential="sk-xxxxxxxx")
try:
    outcome = await session.call_tool(
        spec.require_tool("web_fetch"), {"url": "https://example.com"}
    )
finally:
    await session.close()
```

| 成员 | 说明 |
| --- | --- |
| `spec` / `server` / `generation` / `connected` | 只读观察量 |
| `call_tool(tool, arguments=None, *, read_timeout_s=None)` | 失败抛异常；成功也可能带 `is_error=True` |
| `close()` | 重复调用安全 |
| `__aenter__` / `__aexit__` | 即上下文管理器 |

行为约定：

- 整次调用受 `spec.execution_timeout_ms` 约束；超时抛 `McpRequestError(kind=TRANSIENT, uncertain=not tool.read_only)`。
- 判定为 `SESSION_TERMINATED` 时：**只读工具**重建后透明重放一次，其余抛异常并说明「可能已生效」。

### 4.7 什么时候用哪一层

| 场景 | 用 |
| --- | --- |
| 脚本里看一眼服务器有什么工具 | `open_client` + `list_tool_names` |
| 单次调用、不需要复用连接 | `open_client` + `call_tool_once` |
| 多次调用同一服务器 | `McpSession` |
| 多个服务器、需要授权与作用域隔离 | `McpRuntime`（第 5 章） |

## 5. 运行时 `McpRuntime`

### 5.1 构造

```python
McpRuntime(*, credentials: CredentialResolver | None = None, connector: Connector | None = None)
```

| 参数 | 说明 |
| --- | --- |
| `credentials` | 凭据解析器；默认 `no_credentials`（从不提供凭据） |
| `connector` | 建连函数，默认 `open_client`；仅供测试注入 |

### 5.2 `activate`

```python
await runtime.activate(spec, *, agent_scope="session-1")
```

登记一台服务器。**纯内存、不联网**——加载技能不会因为服务器慢而变慢，服务器宕机也不影响能力清单可见。

- 同作用域、同 `server`、同技能：幂等覆盖。
- 同作用域、同 `server`、**不同技能**：抛 `McpConfigError`。
- runtime 已 `close()`：抛 `McpConfigError("runtime is closed")`。

### 5.3 `call`

```python
await runtime.call(
    *, agent_scope: str, server: str, tool: str,
    arguments: Mapping[str, Any] | None = None, skill: str | None = None,
) -> ToolOutcome
```

执行顺序（**这就是权限边界，不可省**）：

1. `server` 是否在该作用域激活 → 否则 `McpNotActivatedError`；
2. 若给了 `skill`，`server` 是否属于该技能 → 否则 `McpNotActivatedError`；
3. `tool` 是否在白名单 → 否则 `McpToolMissingError`（此时**还没用自己的凭据**）；
4. 取凭据（按地址）、建立或复用连接；
5. 调用并投影结果。

### 5.4 `deactivate` / `activated_servers` / `spec_for` / `close`

| 方法 | 说明 |
| --- | --- |
| `deactivate(*, agent_scope, skill_full_name)` | 移除该技能在该作用域声明的全部服务器，并关闭不再被引用的连接 |
| `activated_servers(*, agent_scope)` | 已激活服务器名（字典序）。**是方法，不是属性** |
| `spec_for(*, agent_scope, server)` | 取声明；未激活返回 `None` |
| `close()` | 关闭全部连接，重复调用安全 |

**踩坑**：`runtime.activated_servers` 忘加括号会打印出 `<bound method …>`，而不是元组。

### 5.5 完整示例

```python
import asyncio
from ghrah.mcp import AgentconfMcpSource, McpRuntime


async def main() -> None:
    with AgentconfMcpSource() as source:
        spec, _ = source.spec_and_credential("阿里云网页解析mcp", skill_full_name="demo/web")

        runtime = McpRuntime(credentials=source)  # 解析器直接复用
        try:
            await runtime.activate(spec, agent_scope="session-1")
            await runtime.activate(other_spec, agent_scope="session-1")
            print("已激活:", runtime.activated_servers(agent_scope="session-1"))

            outcome = await runtime.call(
                agent_scope="session-1",
                server=spec.server,
                tool="web_fetch",
                arguments={"url": "https://example.com"},
                skill="demo/web",
            )
            print(outcome.render_for_model())
        finally:
            await runtime.close()


asyncio.run(main())
```

## 6. 凭据

### 6.1 三种解析器

| 解析器 | 签名 | 适用 |
| --- | --- | --- |
| `no_credentials` | `(url) -> None` | 默认；公开/本地服务器 |
| `StaticCredentials` | `StaticCredentials({url: secret})`，另有 `set` / `delete` | 测试与嵌入场景；密钥在内存里 |
| `AgentconfCredentialResolver` | `(config=None, *, db_path=None)` | 生产；密钥只存在 agentconf |

`AgentconfCredentialResolver` 的匹配规则：provider 的 `base_url` 与 MCP 服务器 `url` 相等（忽略尾部斜杠）。首次取值才打开库，构造无副作用；用完 `close()` 或当上下文管理器。

**踩坑**：agentconf 的 `base_url` / `api_key` 是 pydantic `SecretStr`，`isinstance(x, str)` 恒为 `False`。比较与取值都必须先 `get_secret_value()`——本包内部统一走 `_secret_str()` 收敛。

读取失败（库损坏、schema 不符）只记 warning 并按「没配」处理：凭据读取不该让整个 agent 起不来，缺失会在建连时以明确错误暴露。

### 6.2 占位符替换与 fail-closed

| 配置 | `resolve_headers` 结果 |
| --- | --- |
| `{"Authorization": "Bearer {{auth}}"}` + 密钥 | `Bearer <secret>` |
| 同上，但没有密钥 | 抛 `McpCredentialMissingError` |
| `{"X-Trace": "on"}`（无占位符） | 原样直通，不要求凭据 |

`McpCredentialMissingError` 的文案刻意指向 agentconf：**加一条 provider 记录**，而不是某个 ghrah 子命令。

### 6.3 从 agentconf 装配

`AgentconfMcpSource` 把 agentconf 的 `mcp_servers` 记录翻译成 `McpServerSpec`，并把密钥从 spec 里**摘出去**：

```python
from ghrah.mcp import AgentconfMcpSource

with AgentconfMcpSource(auth_header="Authorization") as source:
    print(source.names())  # 已登记的服务器名
    spec, credential = source.spec_and_credential(
        "阿里云网页解析mcp",
        skill_full_name="demo/web",
        tools=(web_fetch_tool,),  # 白名单通常来自技能配置
    )
    print(spec.headers)  # {'Authorization': 'Bearer {{auth}}'} —— 没有明文
    print(spec.protocol)  # 由记录的 protocol_version_hint 决定
```

构造参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `config` | `None` | 复用已有 `AgentsConfig`（不会被本对象关闭） |
| `db_path` | `None` | 自建连接时的库路径，默认 `~/.agentconf/config.db` |
| `auth_header` | `None` | 取到密钥、但 headers 里没有任何头包含它时，用它承载占位符；`None` 视为配置错误 |
| `auth_template` | `"Bearer {{auth}}"` | 上述注入的头值模板 |

它是**凭据解析器**（`__call__(url)`），可以直接传给 `McpRuntime(credentials=source)`。

### 6.4 `AgentconfMcpSource` API

| 方法 | 返回 | 说明 |
| --- | --- | --- |
| `names()` | `tuple[str, ...]` | 已登记的服务器名 |
| `credential_for_url(url)` | `str \| None` | 按地址在 provider 里找密钥 |
| `credential_for(name)` | `str \| None` | 优先 `credential_ref`（视作 provider 名），再按地址匹配 |
| `__call__(url)` | `str \| None` | 作为 `CredentialResolver` 使用 |
| `spec(name, *, skill_full_name, ...)` | `McpServerSpec` | 翻译记录；stdio / 未知 transport 抛 `McpConfigError` |
| `spec_and_credential(name, **kwargs)` | `(spec, secret)` | 一次拿全 |
| `server_name_for_url(url)` | `str \| None` | 按地址反查记录名 |
| `spec_for_url(url, *, skill_full_name, ...)` | `(spec, secret)` | 见 6.5 |
| `close()` | `None` | 关闭自建连接 |

模块级 `load_spec(name, *, skill_full_name, db_path=None, **kwargs)`：一次性读取并关闭，适合脚本。

字段映射：

| agentconf 字段 | spec 字段 | 说明 |
| --- | --- | --- |
| `name` | `server` | 非法字符压成 `_`，超长截断到 32；纯中文名会退化成 `mcp`，建议显式传 `server=` |
| `url` | `url` | 必填，缺失抛 `McpConfigError` |
| `headers` | `headers` | 含密钥的那段替换成 `{{auth}}` |
| `connect_timeout`（秒） | `connect_timeout_ms` | 空则用 60000 |
| `protocol_version_hint` | `protocol` | `auto`/`modern-first` → modern-first；`legacy`/`handshake` → legacy；`modern`/`2026-07-28` → modern；未知 → modern-first |

**踩坑**：多个请求头同时命中密钥会抛 `McpConfigError`——spec 只允许一个 `{{auth}}`，必须先在 agentconf 里收敛成一个头。

### 6.5 按地址装配：`spec_for_url`

调用方常常只握有一个 URL。`spec_for_url` 让「只知道地址」也能装配：

```python
with AgentconfMcpSource() as source:
    spec, credential = source.spec_for_url(
        "https://mcp.example.com/mcp", skill_full_name="demo/web"
    )
```

| 地址在 `mcp_servers` 里登记过 | 结果 |
| --- | --- |
| 是 | 沿用记录里的 headers / `connect_timeout` / `protocol_version_hint` |
| 否 | 退化成「只带凭据头的最小 spec」；密钥仍按地址从 provider 的 `base_url` 关联 |
| 否，且没有匹配的 provider | 无 headers、无凭据；若需要凭据，建连时会明确报缺失 |

### 6.6 agentconf 侧约定

| 项 | 约定 |
| --- | --- |
| 密钥归属 | `providers` 表：`base_url` **等于** MCP 服务器 url，`api_key` 存密钥 |
| 可选精确指向 | `mcp_servers.connection.credential_ref` 写 provider 名；取不到再回退按地址匹配 |
| `credential_ref` 语义 | agentconf 只当字符串保存，**不读环境变量/文件/凭据服务**；解释权在宿主 |
| 传输方式 | 本包只支持 `streamable_http`；stdio 记录会在装配期被明确拒绝 |

## 7. 工具名、描述与参数 schema

### 7.1 命名规则

| 对象 | 规则 | 违反时 |
| --- | --- | --- |
| `server` | `^[a-z][a-z0-9_]*$`，≤32 字符 | `McpConfigError` |
| `tool` | ≤128 字符；不含空白与控制字符；**大小写、标点原样保留** | `McpConfigError` |

工具名规则刻意宽松：工具名由服务器定义，常见形式包含点号、连字符、大写字母。本包不做任何归一化——归一化只用于「建议」，见 7.3。

### 7.2 描述

`description` 非空，写「何时使用」而不是「内部如何实现」，因为它会被直接渲染进工具目录。

`truncate_description(text, limit=500)` 把描述压成单行再截断：换行会折叠成空格。**必须折叠**——目录是逐行列举的，描述里带换行会把一条记录拆成多条，模型会把后半段当成另一个工具名。

### 7.3 纠错建议

```python
from ghrah.mcp import format_unknown_tool_message, suggest_tool_names

suggest_tool_names("web-fetch", ("web_fetch", "web_search"))  # ('web_fetch', 'web_search')
print(format_unknown_tool_message("web", "web-fetch", ("web_fetch", "web_search")))
# Unknown tool 'web-fetch' on server 'web'.
# Available on 'web': web_fetch, web_search.
# Did you mean 'web_fetch'?
```

两级匹配：先按归一化形式（忽略大小写、`-` 与 `.` 视同 `_`）比对，再退回模糊匹配（`difflib`，cutoff 0.6）。**零网络**——纯本地计算，返回的始终是服务器原名。

**踩坑**：异常消息与这条提示面向不同读者。`McpToolMissingError` 进日志；`format_unknown_tool_message` 进对话，是给模型自我纠正用的通道。

### 7.4 schema 整形

```python
render = tool.render_schema()  # SchemaRender(text, degraded, original_bytes)
if render.degraded:
    logger.warning("schema 超限，已降级: %d bytes", render.original_bytes)
```

超限时不硬塞：降级成「属性名: 类型 (required)」摘要，最多 30 个属性。`compact_json` 用 `ensure_ascii=False`，中文不转义——否则字节数会膨胀数倍，更容易触发上限。

## 8. 结果与投影

### 8.1 `ToolOutcome`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `text` | `str` | 文本内容，多块按顺序以换行连接 |
| `is_error` | `bool` | 服务器声明的错误状态；为真时必须按失败处理 |
| `structured` | `Mapping \| None` | 机器可读的结构化输出 |
| `diagnostics` | `tuple[str, ...]` | 被降级处理的非文本内容说明 |

`render_for_model()` 输出「正文 + 诊断」：先内容、后说明缺了什么，模型才不会把诊断当成工具的真实输出。空内容返回 `"(tool returned no content)"`。

### 8.2 `project_result` 映射

| MCP 内容块 | 投影结果 |
| --- | --- |
| 文本 | 原样进入 `text` |
| 图片 / 音频 | 占位符进 `text`，并记一条 `diagnostics`（二进制负载被丢弃） |
| 资源链接 | `Resource link: <name> (<uri>)` |
| 内嵌文本资源 | 原样进入 `text` |
| 内嵌二进制资源 | 占位符 + 字节数进 `diagnostics` |

### 8.3 使用建议

- `text` 与 `structured` **不要同时**放进模型上下文，否则同一份信息进两遍。
- 需要结构化输出时用 `structured_as_text(outcome)`，别自己 `json.dumps`。
- `diagnostics` 非空意味着这次结果不完整，值得记一条日志。

## 9. 错误处理

### 9.1 异常层次

| 异常 | 何时抛 | 关键字段 |
| --- | --- | --- |
| `McpError` | 所有本包异常的基类 | — |
| `McpConfigError` | 规格/配置非法，建连之前 | — |
| `McpNotActivatedError` | 服务器未激活，或不属于指定技能 | **不带**可用工具清单（授权失败不该泄露远端有什么） |
| `McpToolMissingError` | 工具不在白名单 | `server` / `tool` / `available` |
| `McpCredentialMissingError` | 引用了占位符但没配密钥 | `server` / `url` |
| `McpConnectionError` | 建连失败或连接中断 | — |
| `McpRequestError` | 请求已发出但失败 | `kind` / `code` / `uncertain` / `http_status` / `body_snippet` |
| `McpProtocolError` | 版本无法协商、必要能力缺失 | — |

### 9.2 `FailureKind`

| 值 | 含义 | 典型来源 |
| --- | --- | --- |
| `BAD_ARGUMENTS` | 参数错，重试无意义 | JSON-RPC `-32602` |
| `SESSION_TERMINATED` | 服务端丢弃了会话 | `-32600` + `Session terminated`，或 `-32001`；`404` 且传输层确实持有会话 |
| `TRANSIENT` | 瞬时可重试 | 连接关闭 `-32000`、`408/425/429`、`5xx`、执行超时 |
| `PERMANENT` | 不可重试 | `401/403`、路径写错、未知应用级错误 |

### 9.3 判定函数

```python
classify_rpc_error(code, message) -> FailureKind
classify_http_status(status, *, has_session_id) -> FailureKind
is_session_terminated(*, code, message) -> bool
should_replay(kind, *, read_only) -> bool
```

**踩坑**：`is_session_terminated` 只认两个来源明确的信号，刻意**不**匹配 `broken pipe` / `EOF` / `ClosedResourceError`。那些常在一次调用的**回包中途**触发，此时上游可能已经执行完毕，当成「会话过期可重放」会导致重复副作用。

**踩坑**：`classify_http_status` 的 `has_session_id` 是必须先判断的前置条件。现代无状态协议没有会话标识，它的 `404` 表示路径写错了，误判成会话过期会引发无意义的重建。

### 9.4 `uncertain`

`McpRequestError.uncertain=True` 表示**这次写操作可能已经在服务器上生效**（连接在回包前断开、会话被丢弃、请求超时）。此时不能自动重放，必须先核验外部状态——重放一个已生效的写操作，后果无法撤销。

`should_replay` 只在 `SESSION_TERMINATED` / `TRANSIENT` 且工具**确实标注为只读**时返回 `True`。

### 9.5 HTTP 诊断增强

SDK 把所有非 2xx 折叠成 `-32603 Server returned an error response` 并丢掉状态码与响应体，于是 401（换密钥）和 502（稍后重试）在文本上没有区别。本包在失败后补一次最小探测：

```python
from ghrah.mcp import explain_status, probe_endpoint

probe = await probe_endpoint(url, headers=resolved_headers, secrets=(credential,))
# HttpProbe(status_code=401, content_type="application/json", body_snippet='{"code":"InvalidApiKey"...}')
print(probe.summary())  # HTTP 401 | application/json | {...}
print(explain_status(probe.status_code))
```

它挂在 `open_client` 与 `McpSession.call_tool` 的失败路径上，由 `enrich_request_error` 自动追加，**不改变判定**：`kind` / `uncertain` 原样保留，事后状态码只用于解释原因，不会让一次写调用突然变得可重放。异常文本形如：

```
... (HTTP 401: {"code":"InvalidApiKey","message":"Invalid API-key provided."})
```

`explain_status` 的映射（`None` 表示非错误码）：

| 状态码 | 提示 |
| --- | --- |
| 401 / 403 | 鉴权被拒。常见原因：密钥与端点不属于同一平台，或凭据没有写进请求头 |
| 404 | 地址不存在，检查端点路径与主机名 |
| 405 | 该地址可能只接受 GET（旧版 HTTP+SSE），不是 Streamable HTTP |
| 415 | 网关可能要求不同的 content-type |
| 408 / 425 / 429 | 网关超时或限流，可退避重试 |
| 5xx | 服务端错误，稍后重试 |

探测特性：单次超时 5 秒、响应体截断 300 字符、已知密钥替换成 `***`、网络层就失败时返回 `None`（取证失败不掩盖原始错误）。探测固定用握手代版本 `2025-06-18`，**不跟随** `spec.protocol`——这里要回答的是「HTTP 层收不收这次请求」，不是「协议能不能协商」。

### 9.6 工具级失败不是异常

服务器声明的工具失败（含工具内部异常）以 `is_error=True` 的结果返回。调用方必须检查：

```python
outcome = await runtime.call(...)
if outcome.is_error:
    return f"工具返回失败: {outcome.text}"
```

异常只表示连接、协议或授权层失败。把两者混为一谈，会让你在「工具正常返回了一个错误」时去重试连接。

## 10. 协议协商

### 10.1 三档偏好

| `ProtocolPreference` | SDK `mode` | 行为 |
| --- | --- | --- |
| `MODERN_FIRST`（默认） | `auto` | 先按现代无状态协议探测，收到明确的版本不支持信号后回退到握手协议 |
| `LEGACY` | `legacy` | 直接用握手协议（`initialize`），不做任何回退 |
| `MODERN` | `2026-07-28` | 固定用 `2026-07-28`；对端不支持就失败 |

### 10.2 回退语义

`modern-first` 的回退**只认明确的版本信号**，不因超时触发：把「服务器慢」误判成「协议不对」，会多打一次请求，把慢变成一个更慢的失败。反过来，非协议类异常（网络错、取消）会直接向上抛，不会静默回退。

### 10.3 选择建议

| 情况 | 选 |
| --- | --- |
| 不确定对端实现 | 默认 `modern-first` |
| 对端是明确的握手代实现，且希望少一次探测请求 | `legacy` |
| 内部服务与 SDK 版本已对齐，要求确定性 | `modern` |

## 11. 接入 ability 层

### 11.1 形状

面向模型的 MCP 入口只有一个：`mcp_call`。

```python
{
    "server": "web",  # 服务器名，区分大小写，从技能目录里原样抄
    "tool": "web_fetch",  # 工具名，同上
    "arguments": {"url": "https://example.com"},
    "skill": "demo/web",  # 可选：多个已加载技能可能声明同名服务器时才需要
}
```

`arguments` 刻意是开放对象（`extra=forbid` 只约束四个顶层字段）：不让本地 schema 成为第二套参数校验，参数合法性以服务器为准，错误原样回灌给模型。

### 11.2 装配期注入

运行时经 `AbilityExecutionContext.mcp_runtime` 注入。未接线时明确返回 FAILURE 并说明「本部署未接线」，**不**静默降级。

### 11.3 失败映射

| 异常 | 返回给模型 |
| --- | --- |
| `McpNotActivatedError` | `error` + `note`：先加载声明该服务器的技能 |
| `McpToolMissingError` | `format_unknown_tool_message(...)`：错在哪、有哪些可选、是不是想写另一个 |
| `McpCredentialMissingError` | `error` 原文 |
| `McpRequestError` | `error` 原文；`uncertain` 为真时额外要求先核验外部状态 |

工具级失败（`is_error=True`）也报 FAILURE：包装成「成功但带 error 字段」会让模型以为调用成功并沿错误前提继续推理。

## 12. 排障手册

| 现象 | 可能原因 | 处置 |
| --- | --- | --- |
| `McpCredentialMissingError: No credential registered for MCP endpoint ...` | 配置引用了 `{{auth}}`，但 agentconf 里没有 `base_url` 等于该 url 的 provider | 在 agentconf 加 provider；或改用 `StaticCredentials` |
| 异常里只有 `ExceptionGroup: unhandled errors in a TaskGroup` | 忘了剥 anyio 的分组异常 | 用 `translate_exception`（它会先 `unwrap_exception_group`） |
| `... (HTTP 401: {"code":"InvalidApiKey"})` | 密钥与端点不属于同一平台，或凭据没写进请求头 | 换对平台的密钥；检查 `credential_headers` |
| `... (HTTP 404: ...)` | 端点路径写错 | 核对完整 URL（含 `/mcp` 之类的后缀） |
| `McpNotActivatedError: server 'web' is not activated for this agent` | 没 `activate`，或 `agent_scope` 不一致 | 先激活；确认作用域字符串两侧一致 |
| `McpNotActivatedError: ... belongs to skill 'a', not 'b'` | `call(skill=...)` 传错技能 | 去掉 `skill` 参数，或传声明它的技能全名 |
| `McpToolMissingError` | 工具名不在白名单 | 看 `available`；用 `suggest_tool_names` 自查拼写 |
| 结果 `is_error=True` | 工具自己失败（参数错、外部服务报错） | 按 9.6 当失败处理，读 `text` 看服务器说明 |
| `config 里的 schema 与服务器不一致` | 白名单快照过期 | 用 `list_tool_names` + 远端 `inputSchema` 做一次离线校验并更新快照 |
| `McpConfigError: ... 使用 stdio 传输` | agentconf 记录是 stdio | 本包只支持 streamable-http，改用 HTTP 端点 |
| 建连很慢且最终失败 | 端点不可达、DNS、代理 | 先 `probe_endpoint` 单独看 HTTP 状态码 |

## 13. 限制与边界

| 项 | 现状 | 说明 |
| --- | --- | --- |
| stdio 传输 | 不支持 | 只有 `Transport.STREAMABLE_HTTP`；stdio 记录在装配期被拒绝 |
| 二进制结果 | 丢弃 | 图片/音频/内嵌二进制只留占位符与诊断，无持久化 |
| 工具目录 | 本地快照 | 运行期不拉远端 schema；需要时显式 `list_tool_names` 校验 |
| 多凭据头 | 不支持 | 一台服务器只能有一个 `{{auth}}` 占位符 |
| 自动重试 | 有限 | 只有只读工具的 `SESSION_TERMINATED` 会透明重放一次；其余交给上层 |
| 配置文件 | 不解析 | 本包只接收已构造好的 `McpServerSpec` |
| 工具名改写 | 不做 | 原名透传；调用处必须逐字一致 |
