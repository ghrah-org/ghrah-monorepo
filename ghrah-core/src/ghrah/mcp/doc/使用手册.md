# ghrah.mcp 使用手册

> 本包把明确的本地连接配置转为 MCP 调用。生产授权仍由 AbilityAccessStore 裁定，客户端的激活集合不产生新授权。

## 一、依赖与适用范围

core 的 `mcp` extra 声明 MCP SDK；关闭功能时导入 Core、能力来源和 `ghrah.mcp` 不强制导入 SDK。独立 MCP Provider 配置需要 **agentconf 0.4／schema 6**；使用旧 SDK 时启用该路径会明确报版本错误。

模型配置继续走 agentconf 模型端点。依赖已锁定 `agentconf>=0.4.0,<0.5`（PyPI 发布版），不再使用本地构建的 wheel；旧配置库（schema 5）须先按第七章完成迁移。

当前只执行 streamable HTTP。agentconf 可保存 stdio 或自定义配置，但此宿主明确拒绝这些执行方式；external 凭据引用也尚未实现。旧 `mcp_call` 始终返回已退役的 FAILURE。

## 二、配置 MCP Provider 与具体服务

MCP Provider 保存一套账号／项目的 API Key 和默认认证方式；每个 Server 保存自己的 URL，按 UUID 引用 Provider。不同账号使用不同 Provider；同一厂商的多台服务可以共享同一身份。

```python
from agentconf import AgentsConfig

with AgentsConfig("/path/config.db") as cfg:
    provider = cfg.create_mcp_provider(
        "vendor/account",
        api_key="example-key",
        default_binding={
            "target": "http_header",
            "name": "Authorization",
            "value_template": "Bearer {{auth}}",
        },
    )
    cfg.create_mcp_server(
        "web-tools",
        "streamable_http",
        {
            "url": "https://tools.example.com/mcp",
        },
        auth={"mode": "provider", "provider_id": provider.id, "binding_mode": "inherit"},
    )
```

普通 TUI 提供 transport、Provider、认证来源和继承／覆盖下拉框，不要求手写占位符。Server 仅在明确选择 override 后使用自己的认证方式，Key 仍来自同一 Provider。动态认证头与连接 headers 同名时保存失败；不会靠覆盖顺序决定结果。

模型 Provider 的 URL、格式和 API Key 都不参与 MCP 解析。旧的 `AgentconfCredentialResolver(url)` 明确退役，生产适配不再按 URL 或模型 Provider 名称猜测凭据。

## 三、连接描述与凭据读取分开

`AgentconfMcpSource.connection_spec(name, ...)` 只编译连接描述和无密钥模板，固定 Server ID／revision、MCP Provider ID／revision。默认认证来自 Provider，显式覆盖来自 Server。Provider Key 不放入 spec、模型输入、工具快照、Skill 正文或 ActionChain。

实际调用通过授权与白名单后，才调用 `credential_for_spec` 按同一快照读取 Key；来源或 revision 不匹配时拒绝。inline 静态认证的头值也延迟到 `headers_for_spec`，并纳入结果与错误脱敏。

底层可信调用示意：

```python
from ghrah.mcp import AgentconfMcpSource, McpRuntime, McpToolSpec


async def explicit_call():
    with AgentconfMcpSource(db_path="/path/config.db") as source:
        spec = source.connection_spec(
            "web-tools",
            skill_full_name="diagnostic/explicit",
            tools=(
                McpToolSpec("query", "用户明确选择的查询工具", {"type": "object"}, read_only=True),
            ),
        )
        runtime = McpRuntime(
            credentials_for_spec=source.credential_for_spec,
            headers_for_spec=source.headers_for_spec,
        )
        try:
            await runtime.activate(spec, agent_scope="diagnostic/explicit")
            return await runtime.call(
                agent_scope="diagnostic/explicit", server=spec.server, tool="query", arguments={}
            )
        finally:
            await runtime.close()
```

这是受信诊断示例。生产模型执行必须经过下一节的固定成员与身份适配，不能直接暴露上述任意 server／tool 路由参数。

## 四、生产装配、作用域与生命周期

`SubjectConfig.mcp` 经默认工厂进入 `CoreUnitConfig.mcp`，默认 None 关闭。部署代码构造 `McpDeploymentConfig`，其 `McpSkillBinding` 固定项目、集群、稳定 Agent ID、确定 Skill 引用、具名 Server 和逐成员白名单／schema。关联不是授权，正文或 annotations 不参与许可解释。

每次 Agent 装配创建独立 `AgentMcpService`，注册后绑定当前 run。完整正文读取成功后才离线激活；附件读取不激活。当前正文必须仍可读，成员必须获授、可用且已选择，本地 schema 必须与已提交成员一致。激活不连接端点、不发现工具、不读取 Provider Key。

逐成员 Operation 使用 `execute_mcp_member(call, services)`，从统一 ExecutionServices 的 MCP_RUNTIME 取端口。直接执行与 LLM tool-call 拿到同一服务。受信 scope 由项目、集群、Agent ID 与 run 组成，模型参数只作为远端 payload，不能改变身份或路由。

调用和目录读取会复核当前关系；撤销、改版和取消选择使旧依据失效，先停止接纳再关闭连接，不另起后台轮询。显式卸载、Agent terminate、注册失败回滚、CoreUnit 初始化失败和 stop 都释放所属资源。外部 source 和关系库归各自创建者；失败清理不关闭其他 Agent 的会话。

Provider revision 变化在下一次授权调用前重建本 Agent 的连接，后续请求使用当前 Key／默认绑定。改名不会改变 UUID 关联。Server 被替换、改到另一个 Provider 或自身连接 revision 改变时，旧调用失败，需显式重新加载关联；不会借同名重建的新 Server 延续旧激活。

逐工具包安装、生成 Operation 和模型工具搜索入口需要另外装配。本客户端接线不自动将 MCP 工具加入静态工具数组，也不宣称这些入口已完成。

## 五、失败和外部效果

工具返回 `is_error=True` 必须报告 FAILURE。未接线、未激活、缺 Key、配置变化和请求失败均有明确失败结果，配置源／传输异常原文不回灌给模型。返回文本及结构化内容中回显的已知凭据会被脱敏。

取消原样传播并丢弃连接。明确只读的工具在会话失效时最多重建并重放一次；写调用的断线、会话失效或超时可能已经产生效果，标记 uncertain 并要求先核验外部状态，不自动重放。轮换或关闭不承诺撤销在途效果。

同一会话调用串行化，建连有超时，关闭期间完成的建连会被回收，不继续发工具请求。诊断探测只在生产网络失败路径补充 HTTP 事实；注入 connector 的机器回归不走外网诊断。

## 六、人工烟测入口

新入口使用 agentconf 的 Server 名称和远端工具准确名称；不自动发现、不猜测参数，也不展示 Key：

```sh
uv run --no-sync python ghrah-core/scripts/mcp_named_call.py --help
uv run --no-sync python ghrah-core/scripts/mcp_named_call.py web-tools query \
  --arguments-file /tmp/query-arguments.json --schema-file /tmp/query-schema.json --read-only
```

只有确认工具只读时才传 `--read-only`。退出码 0 为成功，1 为服务端工具失败，2 为配置／请求失败。生产模型不能使用这个诊断入口。旧按 URL 的探测脚本不再代表当前凭据契约。

### 本地测试端点（mock）

没有真实服务、或不想在烟测里访问外部网络时，用仓库自带的本地 mock 端点验证真实传输。它只监听回环地址、按 Streamable HTTP 提供固定工具，不随发布包分发：

```sh
uv run --no-sync python ghrah-core/scripts/mock_mcp_server.py --token local-test-token
# 输出一行 JSON：{"listening": "http://127.0.0.1:8765/mcp", "stats": ".../stats", "port": 8765}
```

工具：`echo`、`add`、`query`、`auth_probe`、`fail`、`slow`、`write_marker`、`large`。`/stats` 返回调用顺序、每次 MCP 请求的鉴权头散列前缀与会话标识，用于确认配置里的凭据确实经由传输送达，而不会回显密钥原文；`/healthz` 只报存活。`--port 0` 让系统分配端口，`--token` 为空时不做 Bearer 校验。

机器回归直接复用同一个脚本（每个用例启动一个子进程，随机端口与随机令牌，不访问外网）：

```sh
uv run --no-sync pytest ghrah-core/tests/mcp/test_local_endpoint.py \
  ghrah-core/tests/ability/test_mcp_wiring.py -q
```

这些用例覆盖完整调用链、Provider 与 inline 两种凭据、工具级错误、执行超时后的会话重建、取消、缺凭据／非白名单在建连前拒绝、卸载后拒绝新调用；`test_mcp_wiring.py` 另有一条用生产 `open_client` 走真实端点完成受信成员调用。

也可以把 mock 端点当成一台普通服务，走上一节的人工入口：把 `--token` 值填成该 Server 在 agentconf 里使用的 Provider Key，再用 `mcp_named_call.py` 按名称调用；`/stats` 会显示每次请求的鉴权指纹。它只能证明本机传输与接线正确，不能替代“已配置真实服务”的人工烟测，也不覆盖 stdio 与 MCP resources／prompts。

## 七、迁移与发布边界

schema 5 的 credential_ref 没有统一的名称／ID 语义，需要 agentconf 的显式迁移映射。迁移可复制确定的模型 Provider Key 到独立 MCP Provider，原模型数据保留，复制后独立维护；含静态认证的记录可保留 inline，旧不透明引用可保留 external。任何无法确定的动态引用都不能依赖 URL 回退。

依赖已切到已发布 agentconf 0.4.0（PyPI）并写入根 `uv.lock`；正式配置库切换仍须完成配置备份与显式迁移，再运行明确指定的真实服务烟测。本地 wheel 时代的联合验证不能替代对已发布版本的回归。
